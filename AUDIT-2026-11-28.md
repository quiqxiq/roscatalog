# Audit Menyeluruh `roscatalog`

> **Tanggal:** 28 November 2026
> **Commit:** `9afdb48` (`main`)
> **Cakupan:** seluruh repo root (`catalog_*.go`, `plan.go`, `types.go`, `builder.go`,
> `command_builder.go`, `fields.go`, `fields/`, `commands/`, `rosrun/`, `mikhmon/`,
> `cmd/`, `docs/`, `README`, `USAGE`, `ROADMAP`, `CHANGELOG`, `MIKHMON`, `tools/`)
> dan relasinya ke `goros/v4`.
> **Sifat:** review read-only. Tidak ada kode yang diubah. Angka dan perilaku

> `golangci-lint`, program probe di luar repo, dan pembacaan kode baris-per-baris.

## 0. Ringkasan Eksekutif

**Vonis singkat:** fondasi desainnya bagus, tetapi proyek ini **belum siap dipakai
sebagai library publik**. Bukan karena idenya salah — pemisahan katalog/eksekusi,
satu koneksi async per router, `Plan` stream/poll, `listen` tanpa `.proplist`,
dan mock server protokol-wire adalah keputusan yang matang. Masalahnya ada di
**kualitas eksekusi**: beberapa command katalog tidak mungkin valid, fitur
unggulan `Subscribe` kehilangan data, koneksi bocor saat reconnect, dokumentasi
tidak bisa diikuti, dan tidak ada CI yang menahan regresi.

| Aspek | Penilaian indikatif | Catatan singkat |
|---|---:|---|
| Visi & arsitektur | 8/10 | Pemisahan data vs eksekusi jelas; model `Plan`/`Delivery`/`Shape` konsisten secara konsep |
| Kualitas data katalog | 5/10 | 125 resource, tetapi 3 action mustahil, 7 resource punya toggle invalid, 33 properti `id` salah |
| Keandalan runtime | 5/10 | Reconnect, watchdog, dan fallback bagus; tetapi bocor goroutine/fd, shared feed kehilangan kolom, error lokal bisa menggantung |
| Ergonomi API | 5/10 | Dua API paralel (global vs `Catalog`), builder kedua yang belum matang, banyak perilaku diam-diam |
| Dokumentasi | 4/10 | 4.200+ baris, tetapi puluhan contoh tidak compile dan saling bertentangan |
| Testing & CI | 5/10 | Coverage inti 78–84%, mock bagus; tidak ada CI, 7 live test hanya env-gated, celah konkurensi besar |
| Keamanan | 3/10 | `cmd/webtest` mengekspos password ke LAN tanpa auth; beberapa default tidak aman |

**Tiga hal yang paling perlu diputuskan lebih dulu:**

1. **Identitas proyek**: ini library Go, produk dashboard, atau kumpulan alat lab?
   Saat ini ketiganya bercampur (`webtest` 1.441 baris + `commands/` 12 ribu baris
   yang tidak dipakai + 5 dokumen setara buku).
2. **Module path**: `go.mod` masih `example.com/roscatalog`, sementara remote
   Git adalah `github.com/quiqxiq/roscatalog`. Tidak ada orang luar yang bisa
   `go get` proyek ini.
3. **Engine**: `goros/` dilacak Git, di-ignore `.gitignore`, identik dengan module
   cache, dan **tidak dipakai build** karena tidak ada `go.work`. Kontributor yang
   mengedit `goros/` tidak akan melihat efek apa pun.

## 1. Peta Proyek yang Sebenarnya

### 1.1 Arsitektur nyata

```

└── module example.com/roscatalog        go.mod (go 1.22)
    ├── package roscatalog               katalog data + Build/Sentence/Plan
    │   ├── catalog_*.go                 125 resource (init() + register)
    │   ├── zz_catalog_enrich.go          119 action generated (init())
    │   ├── types.go / plan.go / builder.go

    │   └── mikhmon/                      overlay + workflow Mikhmon

Angka README (125/175/395) **akurat**. Yang tidak akurat adalah "395 aksi tulis"
(33 di antaranya baca), "12 halaman" (ada 13), dan "katalog belum sepenuhnya
terverifikasi" yang implikasinya lebih besar dari yang ditulis: **90% katalog
belum pernah dicocokkan ke router**.

### 1.3 Yang sudah baik (jangan dirusak saat refactor)

- **Pemisahan tanggung jawab nyata**: root package tidak mengimpor engine; `rosrun`
  adalah adapter; `mikhmon` hanya butuh interface `Executor`. Ini memudahkan
  pengujian dan penggantian transport.
- **Satu koneksi async per router** dengan tag yang dikelola library, bukan satu
  koneksi per stream. Keputusan ini benar dan sudah dijelaskan dengan baik.
- **`listen` tanpa `.proplist`** karena di RouterOS 7.24.6 proplist menekan
  `.dead=true`. Ini temuan lapangan yang berharga dan didokumentasikan.
- **`Plan`/`Delivery`/`Shape`** memisahkan niat pemakai (stream/poll) dari bentuk
  hasil (snapshot/rows/changes). Konsepnya kuat, hanya perlu dirapikan.
- **Fallback `.proplist`**, **watchdog stream**, **drain channel per stream**,
  **`/cancel` eksplisit**, dan **limiter in-flight** adalah penanganan jebakan
  yang jarang ditemukan di library sejenis.
- **Mock server berbicara protokol kawat asli** dan memakai `goros` sungguhan —
  ini jauh lebih baik daripada mock antarmuka biasa.
- **Katalog menyembunyikan secret** dari view rutin (`password`, `secret`, `source`)
  dan sudah ada test-nya.
- **Dokumentasi berbahasa Indonesia** konsisten untuk audiens lokal; ini aset.

## 2. Temuan Kritis (P0)

P0 di sini berarti: **menghalangi pemakaian eksternal atau menyebabkan data
salah/hilang pada pemakaian normal**. Urutan berdasarkan dampak.

### P0-1. Module path placeholder + workspace palsu + engine ganda

**Gejala**

- `go.mod:1` → `module example.com/roscatalog`, padahal remote Git
  `https://github.com/quiqxiq/roscatalog.git`. Perintah di
  `docs/01-getting-started.md:6-7` (`go get example.com/roscatalog@latest`)
  tidak akan pernah berhasil untuk pengguna luar.
- `README.md:8-11` dan `USAGE.md:12,336` menyebut "satu workspace dengan dua
  module" dan `go.work` berisi `use . dan ./goros`. **`go.work` tidak ada**:
  `go env GOWORK` kosong, dan commit `f5ca0f3` menghapusnya.
- `.gitignore:19` berisi `/goros`, tetapi `git ls-files goros` = 75 file.
  Artinya direktori itu **tracked sekaligus ignored**: file lama tetap di Git,
  file baru di dalamnya akan diabaikan.
- Build memakai `goros v4.0.1` dari module cache. `diff -rq goros <cache>` = 0,
  jadi salinan lokal tidak memberi nilai apa pun sampai `go.work`/`replace`
  dipulihkan.
- `README.md:15` dan `USAGE.md:10` mengklaim `rosrun` satu-satunya pengimpor
  `goros`. Faktanya `cmd/example`, `cmd/rosverify`, `cmd/mikhmon-live`, dan
  `tools/probe_print` mengimpor langsung.

**Dampak:** pengguna tidak bisa meng-install; kontributor tidak bisa mengubah
engine; dua sumber kebenaran untuk kode yang sama; klaim arsitektur di dokumen
menyesatkan.

**Perbaikan (pilih satu, jangan campur):**

- **Opsi A (disarankan, sederhana):** hapus `goros/` dari repo, hapus `/goros`
  dari `.gitignore`, tetap bergantung pada `github.com/quiqxiq/goros/v4 v4.0.1`,
  dan perbaiki semua klaim "dua module/workspace" menjadi "satu module + dependency".
  Kelemahan: tidak bisa mem-patch engine tanpa merilis versi baru.
- **Opsi B (jika fork memang akan diubah):** pulihkan `go.work` (`use . ./goros`),
  hapus `/goros` dari `.gitignore`, tambahkan `go work sync`, dan tambahkan CI
  yang menjalankan `cd goros && go test ./...` serta test root dengan workspace.
  Pastikan `go.mod` root tetap punya `require` versi publish agar build tanpa
  workspace tetap jalan.

**Wajib bersamaan:** ubah module path ke `github.com/quiqxiq/roscatalog`
(atau path final lain), lalu perbarui seluruh import dan dokumentasi. Ini
breaking change, tetapi jauh lebih murah sekarang daripada setelah ada pengguna.

### P0-3. Katalog menghasilkan command yang mustahil valid

**Gejala:** `Do(name, ...)` selalu menyusun `Command = r.Path + "/" + name`
(`builder.go:203-208`), dan `Validate` mewajibkan bentuk itu
(`catalog.go:236-242`). Model ini tidak bisa mengekspresikan command root.

| Resource | Definisi | Command dihasilkan | Command sebenarnya |
|---|---|---|---|
| `system-export` | `catalog_interface_system.go:173-177` | `/export/export` | `/export` |
| `system-import` | `catalog_system.go:49-51` | `/import/import` | `/import` |
| `system-reset` | `catalog_system.go:45-47` | `/system/reset-configuration/reset-configuration` | `/system/reset-configuration` |

Selain itu, model `Table` + `Set` salah untuk menu singleton:

| Resource | Masalah | Bukti |
|---|---|---|
| `app-settings` | `Table(...)` membuat `Set` mengirim `=.id=`, padahal `/app/settings` singleton | `catalog_system.go:15-20`; probe: `Set("")` → `ErrSelectorRequired` |
| `tool-sniffer` | idem, `/tool/sniffer` adalah menu settings | `catalog_tools.go:89-111` |
| `console` | `Tool("/execute", nil, nil, ...)` tidak punya argumen `script`, sehingga `Params.Args` ditolak | `catalog_tools.go:113-114`; probe: `argumen "script" tidak dikenal` |
| `tool-ping-status` | `Table("/tool/ping")` membuat view `/tool/ping/print`, yang bukan menu | `catalog_tools.go:119-121` |
| `stub` | menu fiktif `/stub` | `catalog_system.go:53-54` |

**Dampak:** tiga action inti (export/import/reset) tidak pernah bisa dieksekusi;
dua action set tidak bisa dipanggil; beberapa resource adalah jebakan.

**Perbaikan struktural (bukan tambal):**

- Pisahkan `Resource.Path` (menu) dari `Action.Command` (command word). Izinkan
  `Action.Command` eksplisit; `Validate` cukup memastikan command diawali `/`
  dan bukan path+name yang dipaksakan. Tambahkan helper `.Command("/export")`.
- Untuk command root, sediakan `RootAction` atau `Single(...).DoAt("/export", "export", ...)`.
- Untuk menu singleton, gunakan `Single`, bukan `Table`. `Set` pada `Single`
  otomatis `SelNone`.
- Hapus `console`, `menu`, `stub`, dan `tool-ping-status` dari katalog publik
  (pindahkan ke `internal/lab` atau `examples`) sampai punya definisi valid.

### P0-4. Shared feed `Subscribe` kehilangan kolom subscriber kedua (silent data loss)

**Gejala:** `cacheEntry` dibuat dari request subscriber pertama, termasuk
`req.Fields` (`rosrun/cache.go:124-132`). Saat subscriber kedua bergabung,
`recomputeLocked` memperbarui `entry.req.Sentence` menjadi union `.proplist`
(`cache.go:347-385`), tetapi **tidak pernah memperbarui `entry.req.Fields`**.
`Runner.trim()` memakai `Fields` lama (`rosrun/runner.go:376-405`), sehingga
event sudah dipotong ke kolom subscriber pertama sebelum masuk cache.
`trimEvent` untuk subscriber kedua lalu mencari kolom yang tidak ada.

**Bukti reproduksi (out-of-tree):** subscriber A `Only("address")`, subscriber B
`Only("user")`. Sentence ke router sudah `=.proplist=.id,address,user`, tetapi
baris yang diterima B hanya `map[.id:*1]`; `user` tidak pernah muncul, bahkan
setelah beberapa siklus poll.

Test yang ada tidak menangkapnya karena:
- `rosrun/cache_test.go:11-18` membuat request tanpa `Fields`;
- `rosrun/connection_test.go:148-158` dan `live_session_test.go:203-213` hanya
  memeriksa **absen**-nya field subscriber lain, bukan **hadir**-nya field sendiri.

**Dampak:** fitur unggulan (satu upstream, banyak dashboard) kehilangan data
secara diam-diam. Hanya subscriber pertama yang benar.

**Perbaikan:** set `entry.req.Fields = nil` untuk entry cache (union proplist
sudah membatasi payload; `trimEvent` tetap menyaring per subscriber), atau
perbarui ke union setiap recompute. Tambahkan test yang menegaskan kehadiran
field A dan B pada event kedua, `Latest()`, dan setelah restart stream/poll.

### P0-5. Setiap reconnect/Close meninggalkan goroutine dan (saat reconnect) file descriptor

**Gejala:**

- `rosrun/conn.go:120` memanggil `client.AsyncContext(context.Background())`.
  Di `goros`, `asyncLoop` membuat goroutine `<-ctx.Done()` yang tidak pernah
  selesai jika ctx adalah `Background` (`goros/async.go:56-60`). Goroutine itu
  menangkap `*Client`, sehingga client tidak bisa di-GC.
- Saat reconnect, `conn.set(fresh...)` (`conn.go:269`) mengganti client lama
  **tanpa `Close()`**. Socket lama tetap terbuka sampai finalizer (yang tidak
  akan jalan karena goroutine masih memegang client).

**Bukti terukur:** 5 reconnect → fd 9→14 dan goroutine `asyncLoop` +5;
5 `Open`/`Close` berurutan → goroutine +5.

**Dampak:** daemon multi-router dengan link tidak stabil akan kehabisan fd dan
menumpuk goroutine. `Manager` yang membuka/menutup sesi karena grace juga bocor.
Tidak terlihat di test karena tidak ada pemeriksaan fd/goroutine.

**Perbaikan:**

1. Buat `ctx, cancel := context.WithCancel(context.Background())` per koneksi,
   simpan `cancel` di `managedConn`, berikan ctx itu ke `AsyncContext`.
2. Saat replace dan `Close`, panggil `cancel()` **dan** `client.Close()` untuk
   client lama.
3. Tambahkan test kebocoran berbasis `runtime.NumGoroutine` dan `/proc/self/fd`
   (Linux) setelah reconnect dan setelah Close.

Catatan: jangan memberi ctx berumur pendek ke `AsyncContext`; ctx harus hidup
selama koneksi.

### P0-6. Tidak ada CI; gerbang kualitas dasar tidak berjalan

**Gejala:**

- Tidak ada `.github/workflows` di root. Satu-satunya workflow ada di
  `goros/.github/workflows/go.yml`, dan GitHub Actions **tidak** membaca
  workflow di subdirektori — jadi efektifnya tidak ada CI.
- `gofmt -l .` (di luar `goros/`) melaporkan 3 file:
  `cmd/webtest/main.go`, `command_builder.go`, `mikhmon/client.go`.
- `golangci-lint run ./...` menemukan errcheck/staticcheck di `cmd/`,
  `rosrun/`, `mikhmon/`, plus `unused` (`watchHealth`).
- `go test ./...` tidak menjalankan test `goros` (module terpisah).
- 7 test live di-skip berdasarkan env, bukan build tag; `TestLiveListenRemoval`
  menulis ke router jika env diisi.

**Dampak:** regresi kualitas tidak tertangkap; "`go test -race` lulus" tidak
berarti aman karena bug P0-4/P0-5 tidak punya test.

**Perbaikan:** tambahkan `.github/workflows/ci.yml` dengan:
`gofmt -l` (gagal jika ada output), `go vet ./...`, `go test ./... -race -count=1`,
`go build ./docs/examples/...`, link checker Markdown, dan (opsional) job
`goros` terpisah dengan `cd goros && go test ./...`. Tambahkan `//go:build live`
pada test yang menyentuh perangkat.

## 3. Temuan Serius (P1)

### 3.1 `rosrun` — keandalan dan konkurensi

| # | Temuan | Lokasi | Bukti/dampak | Perbaikan |
|---|---|---|---|---|
| R1 | **Data race `entry.req`** | `cache.go:265-266` (baca) vs `377-379` (tulis di bawah `c.mu`) | `go test -race` pada `Subscribe`/`Close` bersamaan melaporkan read/write; copy struct bisa robek | Snapshot `req` di bawah lock di `startStreamLocked`, teruskan sebagai parameter ke `runStream` |
| R2 | **`Manager.Subscribe` refcount leak + race** | `manager.go:371-383` (`onClose` dipasang setelah `Subscribe`), `cache.go:45-53` | Jika upstream error/ctx batal sebelum assignment, `fireClose` berjalan dengan `nil`, `Release` tidak pernah dipanggil; 30 iterasi menghasilkan `refs` final 2–4 | Jadikan `onClose` parameter internal yang dipasang sebelum upstream dimulai |
| R3 | **`forward` menelan error lokal dan menggantung** | `session.go:233-313`; `runner.go:650-655,664-678` | Overflow queue (error lokal, koneksi sehat) dianggap "reconnect", lalu `epochs.wait` menunggu epoch yang tidak akan datang; stream yang berakhir bersih juga macet dengan `KindReconnecting` selamanya | Bedakan error lokal vs koneksi; emit `KindError` terminal untuk overflow; jangan tunggu epoch bila `!isDown()`; beri timeout |
| R4 | **Limiter tidak peduli ctx → sesi bisa macet permanen** | `limiter.go:46-66`; `runner.go:275-316` | `l.sem <- struct{}{}` memblokir tanpa select; slot dilepas setelah `RunArgs` kembali. 8 command menggantung = semua command berikutnya diblokir, ctx tidak bisa membatalkan | `acquire(ctx)`; watchdog per command yang menutup koneksi; tolak sentence non-terminating di `Exec`/`Once` |
| R5 | **Cache menyuntik `.proplist` ke view yang melarangnya** | `cache.go:373-380,434-453` | `Subscribe` pada `system-resource/list` mengirim `=.proplist=...`, padahal view sengaja `WithoutServerProplist` (`catalog_interface_system.go:107`) | Tambahkan penanda `ServerProplist`/`ProplistAllowed` ke `ros.Request`; jangan rewrite bila false |
| R6 | **Kunci shared feed mengabaikan `Every`** | `cache.go:409-419`; `scheduler.go:101-115` | Dua subscriber poll 5s dan 30s berbagi entry; scheduler memakai `Every` pemilik pertama | Masukkan `Every` (dan `ResourceID`/`View`) ke `menuKey`, atau satukan dengan `Request.Fingerprint` |

## 7. "Lebih Mudah Digunakan" — Ergonomi dan Kesesuaian

### 7.1 Tentukan audiens

Saat ini proyek berbicara kepada tiga audiens sekaligus:

1. **Developer Go** yang ingin katalog + transport RouterOS.
2. **Operator ISP** yang ingin dashboard siap pakai (`cmd/webtest`).
3. **Peneliti/Mikhmon** yang ingin pemetaan command dan workflow.

Katalog + `rosrun` jelas untuk (1). `webtest` dan `mikhmon` adalah produk terpisah.
Saran: pertahankan **library** sebagai inti; pindahkan dashboard ke repo/aplikasi
sendiri; jadikan `mikhmon` package opsional yang terdokumentasi sebagai overlay.

### 7.2 Satu API, bukan dua

Saat ini ada dua pintu masuk dengan perilaku berbeda:

- `ros.Lookup` / `ros.All` / `ros.ByGroup` — global, linear scan, pointer global.
- `ros.Builtin().Lookup` / `.All` — O(1), tetapi membuat map+slice baru tiap
  panggilan dan tetap berbagi pointer.

Saran: jadikan `Builtin()` sebagai satu-satunya pintu (cache hasilnya), atau
pertahankan global tetapi delegasikan ke satu `Catalog` singleton yang di-cache.
Kembalikan salinan dangkal yang aman atau sediakan `Clone()`.

### 7.3 Model command yang benar

Pisahkan tiga konsep yang sekarang bercampur di `Path`:

| Konsep | Contoh | Representasi |
|---|---|---|
| Menu | `/ip/hotspot/user` | `Resource.Path` |
| Command | `/export`, `/system/reset-configuration` | `Action.Command` eksplisit |
| Selector | `.id`, `numbers`, `number` | `Action.Selector` + validasi |

Validasi harus memeriksa:
- `Action.Command` ada di `commands.ByPath` (atau path+verb dikenal),
- selector cocok dengan verb (`set` → `.id`, `run` → `number`, `move` → `numbers`),
- `enable/disable` hanya bila properti `disabled` ada,
- `Set` tidak mengirim properti read-only (`dynamic`, `type`, `place-before`).

### 7.4 Hentikan perilaku diam-diam

Banyak bug berasal dari "menerima lalu mengabaikan":

| Perilaku sekarang | Seharusnya |
|---|---|
| `StreamEvery(10s)` pada view `follow` diterima tetapi `Every` diabaikan | Tolak atau dokumentasikan bahwa tidak berpengaruh |
| `Diff` + `Stream` diterima, diff diabaikan | Tolak dengan `ErrDeliveryUnsupported` |
| `Seed` pada non-listen diabaikan | Tolak |
| `Params.Tag` diteruskan + library menambah tag | Tolak/strip; dokumentasikan |
| `Query` properti apa pun diterima | Validasi terhadap `Filters` (opsional ketat) |
| `Action` argumen tak dikenal diterima | Validasi atau `Strict` mode |
| `PrintCmdBuilder` `count-only` tidak set `CountOnly` | Perbaiki atau hapus |
| `Do("ping","8.8.8.8")` menjadi `=numbers=` | Tolak bentuk ambigu |
| `SameStatus` mengabaikan Uptime | Perbaiki |

### 7.5 Nama dan tipe

- `MikroTik` adalah **sesi**, bukan router. Pertimbangkan `Session` (breaking,
  tapi lebih jelas).
- `Watch` vs `Subscribe`: dua semantik pengiriman (blocking vs drop) tanpa nama
  pembeda. Beri nama `Watch` (lossless, backpressure) dan `Subscribe`
  (coalescing, lossy) dan dokumentasikan perbedaannya di godoc.
- `Remove` = `Unregister`; pilih satu.
- `Retain/Drop` memakai string bebas sebagai identitas hold; ganti dengan token
  atau minimal dokumentasikan.
- `Filter` (method) vs `Filters` (field); `P` satu huruf; `Uparam` bukan istilah
  baku.
- `Event` union type; pertimbangkan event bertipe atau tabel field valid per
  `Kind`.

### 7.6 Default yang lebih aman dan sesuai

| Default sekarang | Saran |
|---|---|
| Status ping `8.8.8.8` aktif | `Disable=true` atau target wajib; pisahkan API health vs ICMP |
| `-insecure=true` di `roscheck`/`multicheck` | default `false`, opt-in untuk lab |
| `webtest` bind `:8080` | `127.0.0.1:8080`, auth token, redaksi password |
| `MaxBuffered` 8192 (sesi) vs 65536 (`New`) | satu default, dokumentasikan |
| `Config.Stream` deprecated tapi masih ada | hapus setelah migrasi, atau gunakan sebagai fallback |
| `StreamEvery` maks 5s | kebijakan proyek, tetapi beri opsi eksplisit untuk 10–60s dengan peringatan beban |
| `Poll` wajib `Every` | beri default `PollEvery` bila kosong |

### 7.7 Quickstart 5 menit yang disarankan

```go
package main

import (
    "context"
    "fmt"
    "os"

    ros "github.com/quiqxiq/roscatalog"
    "github.com/quiqxiq/roscatalog/rosrun"
)

func main() {
    ctx := context.Background()
    sess, err := rosrun.Open(ctx, rosrun.Config{
        Address:  os.Getenv("ROS_ADDR"),
        Username: os.Getenv("ROS_USER"),
        Password: os.Getenv("ROS_PASS"),
        Status:   rosrun.StatusConfig{Disable: true}, // API health saja
    })
    if err != nil { panic(err) }
    defer sess.Close()

    res, _ := ros.Lookup("interface")
    req, err := res.Build("list", ros.Once(), ros.Params{})
    if err != nil { panic(err) }
    rows, err := sess.Once(ctx, req)
    if err != nil { panic(err) }
    for _, r := range rows {
        fmt.Printf("%-16s %s\n", r["name"], r["running"])
    }
}
```

Persyaratan: Go 1.22+, RouterOS 7.9+, user API `read` (bukan `admin`), port 8728
atau 8729+API-SSL. Troubleshooting: API disabled, port salah, auth gagal,
module path (sementara pakai `replace`).

## 11. Penutup

Proyek ini punya **inti yang layak**: model katalog + `Plan` + adapter
reconnect-aware adalah kombinasi yang tepat untuk tooling ISP. Yang membuatnya
belum "mudah digunakan dan sesuai" bukan kekurangan ide, melainkan **jarak antara
klaim dan realitas**: dokumentasi menjanjikan API yang sudah berubah, katalog
memuat command yang tidak ada, fitur shared feed kehilangan data, dan tidak ada
CI yang menjaga semuanya.

Jika hanya tiga hal yang bisa dikerjakan, kerjakan ini:

1. **Perbaiki identitas & build** (module path, `go.work`/engine, CI) — tanpa ini
   proyek tidak bisa dipakai orang lain.
2. **Perbaiki kebenaran data & runtime** (command invalid, shared feed fields,
   leak reconnect) — tanpa ini proyek berbahaya dipakai produksi.
3. **Tulis ulang quickstart + test dokumentasi** — tanpa ini pengguna tidak akan
   pernah sampai ke inti yang bagus.

Sisanya (ergonomi builder, satu sumber kebenaran, pemisahan dashboard) adalah
pekerjaan yang lebih mudah setelah tiga fondasi itu benar.
